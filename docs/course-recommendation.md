# 코스 추천 기능 명세

- 작성일: 2026-09-08
- 상태: 대화에서 정리한 개발 기준. 기능 구현 완료를 의미하지 않음.
- 목적: 선택한 맛집을 출발지로 관광지와 맛집을 섞은 코스를 추천하고, 실제 이동 경로와 편집 기능을 제공한다.
- 변경 사항 (2026-09-08): 카테고리별 한 곳·고정 순서 규칙을 관광지·맛집 혼합 코스로 대체한다. 코스당 4~5곳은 출발 맛집을 포함하는 기준으로 해석한다.
- 구현 진행 (2026-09-08): PostGIS SQL 원격 적용 후 실제 맛집 검색과 TourAPI 관광지 호출을 확인했다. 지도 화면에 코스 생성·편집 패널을 연결했다. 현재 가까운 장소를 연결하는 초안이며 시간·테마·신뢰도 평가와 실제 길찾기는 미구현이다.

## 현재 지도 화면에서 사용하는 방법

1. 맛집 선택 후 지도 상단의 **이 맛집에서 추천 코스 만들기**를 누른다.
2. 출발지 포함 4곳/5곳, 맛집도 함께/관광지 중심을 선택하고 **추천 코스 생성**을 누른다.
3. 요청마다 관광지 API와 주변 맛집을 조회해 직전 장소에서 가까운 후보를 연결한다. 관광지 중심에서는 출발 이후 관광지만 선정한다.
4. 지도 순번과 카드 목록으로 초안을 확인한다. 장소를 누르면 위치로 이동하고 패널을 접는다.
5. 출발지를 제외한 장소는 위·아래 이동과 삭제가 가능하다. 미포함 주변 맛집은 최대 5곳을 유지하는 범위에서 코스 끝에 추가한다.
6. 변경 즉시 지도 번호와 구간 직선거리 합계를 갱신한다. 실제 길찾기·영업시간 검증 결과로 표시하지 않는다.

선택 조건에 맞는 후보가 부족하면 3km까지 확인하고, 그래도 부족하면 조건 변경을 안내한다. 조회 실패 시 기존 초안을 유지한다. 닫거나 지도 탭을 벗어나면 초안은 사라지며 DB·파일·로컬 저장소에 보관하지 않는다. 새로 추천받기는 최신 데이터를 다시 조회하는 기능이며 다른 결과를 보장하지 않는다.

## 1. 핵심 사용자 흐름

1. 사용자가 맛집 하나를 출발지로 선택한다.
2. 출발 날짜·시간, 테마, 이동수단, 전체 소요 시간을 입력한다.
3. 출발 맛집 주변 관광지와 다른 맛집 후보를 조회한다.
4. 방문 가능한 후보 중 정보 신뢰도, 테마 일치도, 거리를 고려해 선정한다.
5. 출발 맛집을 포함해 **4~5곳의 혼합 코스**를 생성한다. 출발 이후 카테고리 순서는 고정하지 않는다.
6. 지도에 장소와 실제 이동 경로, 거리·시간을 표시한다.
7. 사용자가 장소를 삭제하거나 순서를 변경하면 경로와 일정을 재계산한다.
8. 코스에 포함하지 않은 주변 맛집도 별도로 안내한다.

출발 시간은 맛집에서 식사를 마치고 이동을 시작하는 시간으로 해석한다. 초기 일정 계산에는 출발 맛집에서의 식사 시간을 중복 포함하지 않는다.

## 2. 후보 조회와 데이터 연결

| 항목 | 기준 |
| --- | --- |
| 기준 좌표 | 사용자가 선택한 맛집의 위도·경도 |
| 기본 반경 | 직선거리 2km |
| 확대 반경 | 후보가 부족하면 최대 3km |
| 후보 종류 | 관광지, 맛집 |
| 최초 구성 | 출발 맛집 포함 총 4~5곳, 이후 관광지·맛집 자유 조합 |
| 제외 대상 | 좌표 오류, 중복 장소, 필수 조건을 충족하지 못한 장소 |

맛집은 Supabase의 PostGIS 반경 검색으로 조회하고, 관광지는 기존 TourAPI에 같은 출발 좌표와 반경을 전달해 매 요청마다 실시간 조회한다. Next.js 서버에서 두 결과를 공통 장소 형식으로 합친다. 관광지 API 응답은 DB·파일에 저장하지 않으며, 서버·브라우저 캐시를 사용하지 않는다. PostGIS SQL은 원격 DB에 적용하고 샘플 호출을 확인했다. 카페는 필수 구성에서 제외하며, 추후 도입 시 공급원과 분류 기준을 정한다.

두 데이터는 동일 ID로 연결하는 것이 아니라, 맛집 좌표 주변의 장소를 공간적으로 연결한다. 원본 식별자는 `source`와 `sourceId`를 함께 보관해 공급원 간 ID 충돌을 방지한다. 테마 비교를 위해 맛집·관광지에 공통 테마 태그 체계를 적용한다. 출발 맛집과 이미 선택한 장소는 다음 후보에서 제외한다.

반경은 출발 맛집 기준의 후보 수집 범위다. 각 장소를 중심으로 반경을 반복 확장하지 않는다. 반경 안의 장소끼리도 멀리 떨어질 수 있으므로, 실제 순서의 모든 인접 구간에서 이동 거리를 확인한다.

## 3. 검색 및 추천 기준

초기 버전은 **조건·태그 기반 검색**을 사용한다. 지역, 카테고리, 반경 등은 필터로 제한하고 테마 태그 일치도를 비교한다. 한국어 자연어 검색과 벡터 검색은 후속 확장이다.

### 필수 조건

- 해당 순서의 예상 도착 시간에 방문할 수 있어야 한다.
- 영업시간, 휴무, 브레이크타임, 입장 마감과 체류 시간을 고려한다.
- 전체 이동·체류·대기 시간이 사용자의 일정 범위 안에 들어와야 한다.
- 운영시간이 누락된 장소를 방문 가능하다고 단정하지 않는다. 포함 여부는 아래 미결정 항목에서 확정한다.

### 후보 우선순위

| 우선순위 | 항목 | 평가 근거 |
| --- | --- | --- |
| 1 | 정보 신뢰도 | 공식·직접 확인 출처인지, 최근 검증 여부, 다른 출처와의 일치 여부 |
| 2 | 테마 일치도 | 사용자가 선택한 테마와 장소의 공통 태그 일치 정도 |
| 3 | 거리 | 직전 방문지에서 가까운 순, 전체 이동 동선도 함께 검토 |

정보가 많다는 것과 정확하다는 것은 다르다. 정보 완전성만으로 신뢰도를 확정하지 않으며, 공식 출처라도 최신성·충돌 여부를 확인한다.

초기 대화의 **거리 50점 + 조건 일치 30점 + 데이터 완전성 20점**은 검토안이다. 현재 개발 기준은 위의 우선순위이며, 가중 합산 점수나 신뢰도 등급의 구체적인 계산식은 확정되지 않았다.

장소 선정 우선순위와 방문 순서는 구분한다. 단순히 장소별 상위 후보를 연결하지 않고, 관광지·맛집 조합이 전체 일정에서 방문 가능한지 확인한다.

## 4. 최초 코스 생성 규칙

출발 맛집만 고정하고 이후 카테고리와 순서는 제한하지 않는다. 코스당 장소 수는 출발 맛집을 포함해 4~5곳으로 해석한다. 서로 다른 코스를 제시할 수 있으며 한 번에 제공할 코스 개수는 별도 결정한다.

예시:

- 맛집 A → 관광지 B → 관광지 C → 관광지 D → 관광지 E
- 맛집 A → 관광지 B → 맛집 C → 관광지 D → 맛집 E
- 맛집 A → 맛집 B → 관광지 C → 관광지 D

1. 출발 맛집 주변의 관광지·맛집 후보를 수집한다.
2. 조건과 추천 우선순위를 적용해 후보 조합과 방문 순서를 만든다.
3. 실제 이동 시간과 체류 시간을 반영해 조합의 방문 가능 여부를 검증한다.
4. 시간에 맞지 않으면 출발지를 유지하며 이후 순서 또는 후보를 바꿔 검토한다.
5. 가능한 조합이 없으면 완성 가능한 코스가 없다는 이유를 안내한다.

맛집을 반드시 추가하거나 카테고리를 번갈아 배치하지 않는다. 추가 맛집에 머무는 시간은 일정에 포함한다. 4곳 미만의 부분 코스 자동 생성 정책은 미결정이며, 장소 수를 채우기 위해 방문 불가능한 장소를 넣지 않는다. 생성 후 사용자 삭제로 4곳 미만이 되는 것은 허용한다.

### 코스 주변 맛집 안내

- 방문 예정 장소 또는 이동 경로 근처에 있는 맛집을 코스와 별도 목록·마커로 안내한다.
- 코스에 포함된 맛집과 주변 참고 맛집을 구분하고 동일 장소를 중복 추천하지 않는다.
- 주변 맛집은 자동으로 방문 목록에 추가하지 않으며, 코스 시간에도 포함하지 않는다.
- 경로 근처 여부는 출발지 반경만으로 판단하지 않는다. 장소까지의 거리 또는 경로 이탈 거리를 확인하며, 근처의 기준과 표시 개수는 별도 결정한다.
- 사용자가 주변 맛집을 코스에 추가하는 기능과 추가 후 최대 장소 수는 후속 결정 사항이다.

## 5. 지도와 실제 경로

- 지도에 방문 순서가 표시된 장소 마커를 제공한다.
- 길찾기 API로 현재 방문 순서의 모든 인접 구간에 대해 실제 경로를 조회한다.
- 반환된 경로를 지도에 표시하고 구간별 거리·예상 이동 시간과 전체 소요 시간을 제공한다.
- 실제 이동 시간으로 예상 도착·출발 시간을 계산하고 운영시간을 다시 확인한다.

현재 카카오 지도 연동을 표시 기반으로 활용한다. 지도 표시 API와 길찾기 API는 별도 기능이다. 도보·대중교통 등 지원할 이동수단과 해당 경로 제공업체는 확정이 필요하다.

직선 연결선을 실제 도보·대중교통 경로로 표시하지 않는다. 조회 실패 시 경로 확인 실패를 안내하고 확인되지 않은 이동 시간을 확정값으로 표시하지 않는다.

## 6. 코스 편집과 재계산

- 출발 맛집은 고정한다.
- 이후 장소는 삭제할 수 있다.
- 이후 장소 순서는 드래그 또는 위·아래 버튼으로 변경할 수 있다.
- 최초 생성과 사용자 편집 모두 출발 이후 관광지·맛집의 자유로운 순서를 허용한다.

변경 시 다음 항목을 함께 갱신한다.

1. 변경된 순서의 구간별 실제 경로
2. 지도 경로와 마커 순번
3. 구간별 거리·이동 시간 및 전체 소요 시간
4. 각 장소의 예상 도착·출발 시간
5. 운영시간과 전체 일정 충족 여부

편집 후 방문이 어려워진 장소는 경고한다. 사용자 순서를 임의로 되돌리거나 장소를 자동 교체하지 않는다. 재계산 중임을 표시하고, 연속 편집 시 가장 최근 순서의 응답만 반영한다.

중간 장소 삭제 시 앞뒤 장소를 직접 잇는 경로를 다시 조회한다. 이후 장소를 모두 삭제하면 출발 맛집만 표시하고 이동 경로를 제거한다. 코스가 변경되면 주변 맛집 안내도 새 동선을 기준으로 갱신한다.

## 7. 필요한 데이터와 구현 제안

아래는 구현을 위한 제안이며, 실제 DB 스키마나 API 계약은 아직 확정되지 않았다.

| 데이터 | 필요한 내용 |
| --- | --- |
| 장소 | 공급원·원본 ID, 이름, 카테고리, 좌표, 주소, 테마 태그 |
| 운영 정보 | 날짜별 운영시간, 휴무, 브레이크타임, 입장 마감, 예상 체류 시간 |
| 신뢰도 근거 | 정보 출처, 출처 갱신일, 직접 확인일, 정보 충돌·누락 여부 |
| 코스 입력 | 출발 맛집, 날짜·시간, 이동수단, 테마, 전체 시간 한도 |
| 코스 결과 | 순서가 있는 장소 목록, 구간별 경로·거리·시간, 도착·출발 시간, 경고, 별도 주변 맛집 목록 |

장소 ID·좌표뿐 아니라 추천 이유와 정보 확인 필요 여부도 결과에 포함하면 사용자가 선택 근거를 이해할 수 있다.

### 기술 선택 방향

- 초기 버전: 기존 Next.js와 Supabase에서 필터·태그 검색, 소수 후보 조합 비교를 구현한다. Python은 필수가 아니다.
- 공간 검색: Supabase PostGIS로 주변 맛집을 조회하고, TourAPI 관광지 결과와 서버에서 합친다.
- 자연어 검색 확장: 한국어 질의를 장소 설명과 비교할 임베딩 모델과 pgvector를 검토한다. Python FlagEmbedding/BGE-M3는 후보이며 실제 검색 품질 검증이 필요하다.
- 복잡한 시간 제약 확장: Python OR-Tools를 검토한다. 실제 이동 시간은 별도 길찾기 API에서 공급해야 한다.

## 9. 개발 전 확정할 항목

- 지원 이동수단과 길찾기 API 제공업체
- 한 번에 제시할 코스 개수, 코스 간 장소 중복 허용 정도
- 4곳 미만의 부분 코스 제안 여부
- 주변 맛집의 근접 거리 기준·표시 개수 및 코스 추가 기능
- 반경 확대의 초기 구현은 출발지 외 후보 4곳 미만 기준이다. 방문 가능 조합 부재에 따른 추가 확대는 코스 생성 단계에서 결정한다.
- 공통 테마 목록과 복수 테마 일치도 계산 방식
- 정보 신뢰도 등급·정렬 규칙과 누락·충돌 데이터 처리
- 운영시간 미확인 장소의 포함 여부
- 관광지·추가 맛집 기본 체류 시간과 사용자 수정 가능 여부
- 대기 시간 허용 여부와 최대 허용 시간

## 10. 완료 확인 기준

- [ ] 선택한 맛집이 출발지로 유지된다.
- [ ] 2km 후보 조회와 필요한 경우 3km 확대가 적용된다.
- [ ] 최초 코스는 출발 맛집 포함 4~5곳이며 이후 관광지·맛집을 자유롭게 조합한다.
- [ ] 관광지만 이어지는 코스와 맛집이 섞인 코스를 모두 지원한다.
- [ ] PostGIS 맛집 결과와 TourAPI 관광지 결과를 합치고 출발지·중복 장소를 제외한다.
- [ ] 코스 주변 맛집은 방문 장소와 구분해 안내하고 코스 시간에 자동 합산하지 않는다.
- [ ] 실제 도착·체류 시간을 기준으로 방문 가능 여부를 확인한다.
- [ ] 추천 우선순위와 정보 미확인 상태를 설명할 수 있다.
- [ ] 지도에 실제 경로와 구간별 거리·시간이 표시된다.
- [ ] 장소 삭제와 순서 변경 후 경로·일정이 갱신된다.
- [ ] 빠른 연속 편집에도 이전 응답이 최신 코스를 덮어쓰지 않는다.
- [ ] 후보 없음, 경로 조회 실패, 운영시간 누락, 편집 후 방문 불가 상태를 안내한다.

요구사항 변경 시 이 문서의 관련 규칙과 완료 확인 기준을 함께 수정한다. 미결정 항목을 확정할 때는 결정 내용과 날짜를 기록한다.
